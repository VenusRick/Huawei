# P1.5 真实行为数据采集任务清单（需人工执行）

> 目标：为"精细化行为识别"与"跨平台适应性"提供真实试次真值。
> 每一次受控行为试次 = 一条 manifest 记录 + 一个 pcap。
> 我方已就绪：manifest 校验器（--mode validate-data）、行为窗口全链、
> 时间校准与导入管线。**采集完成即可直接回填跑真实成绩。**

## 一、场景矩阵（题面要求，按优先级）

| 组 | 应用 | 动作 | 平台 | 试次数/平台 | 优先级 |
|---|---|---|---|---|---|
| IM | 微信 或 WhatsApp | 文字聊天（发10条短消息） | Android/iOS/PC | 5/10/20 档 | P0 |
| IM | 同上应用 | 语音通话（>=1分钟） | 三平台 | 5/10/20 档 | P0 |
| IM | 同上应用 | 视频通话（>=1分钟） | 三平台 | 5/10/20 档 | P0 |
| Social | Facebook/X/Instagram 任一 | 发文字帖（3条） | 三平台 | 5/10 档 | P1 |
| Anonymous | Tor Browser | 浏览+下载 | PC优先 | 5/10 档 | P1 |
| Anonymous | Psiphon 或 Session | 常规使用 | Android/PC | 5/10 档 | P1 |

注意：**各动作必须确有数据**（语音消息≠语音通话）；每试次独立抓包、
前后各留 >=2s 纯背景（不操作）。

## 二、每试次必填字段（manifest 一行）
capture_id（一次连续采集的ID，同组不拆分）/ trial_id / platform /
device_id / app / app_version / behavior / behavior_start / behavior_end
（相对 pcap 首包秒数）/ network_env / pcap（文件名）/ label_source /
terminal_ip（可见终端 IP，方向基准）

## 三、三端操作要点
- Android：抓包用 tcpdump（root/adb）或 PC 热点侧抓包；事件用
  Accessibility/ADB logcat 或人工记录器
- PC：tcpdump/Wireshark 抓包 + `scripts/event_recorder.py` 记录动作时刻
- iOS：AP（Mac 热点/路由器）侧抓包 + 独立动作记录器（手机旁操作）
- 时间校准：记录器启动墙钟与抓包启动墙钟同时记下，差值写 network_env
  备注（如 "clock_offset=+0.8s"）；label_source=manual_verified 最稳

## 四、交付回传
pcap 目录 + events.jsonl（记录器输出）+ 手填 manifest.jsonl ->
`python -m src.pipeline --mode validate-data --manifest ...` 通过即入库
