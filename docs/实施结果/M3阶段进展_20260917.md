  引用规则/有效性）/ feature_effectiveness.csv（五级判定原始表）/

- 展示逻辑链贯穿：哪些特征有区别->选择了哪些->条件组合->如何变DPI规则->
  成功/失败样本

### 2. 特征有效性口径固定（建议.md 第七点）
- A=自动输出全集；五级判定（可正确计算/训练推理定义一致/验证集判别证据
  ANOVA p<0.05/可被引擎使用）-> E；EffectiveRate=|E|/|A|
- 每特征判定原因留档；无法判断保留 pending
- selected/all=保留比例非有效率（catalog 与 run_report 显式标注）
- 人工修订后 U/UsableRate 由 revise-rules 流程的 edits 记录支撑

### 3. revise-rules 模式（--mode revise-rules）
- 结构化编辑（disable/enable/edit conditions）；只认合法 op 白名单，
  未知函数与任意Python表达式天然禁止
- 校验：rule_id 存在、feature 必须在已部署 selected、value 数值；
  违规明确拒绝非零退出
- 验证集回放 diff（revision_diff.json，不读测试数据）；
  新版本目录发布不覆盖原 bundle

### 4. e2e 实证（output/p2_e2e/）
- mine -> analysis/ 三件自动生成（非手工模板）
- 合法修订：禁用 STAT_0002 -> 新 bundle 4 规则；回放 6 样本 0 变化
  （该规则冗余，如实记录）；原 bundle 未改动
- 非法编辑：未部署特征 ___nope___ -> "拒绝发布"明确报错
- evaluate -> analysis/ 五件齐（修 ENS_0001 confidence=None 格式化崩）
