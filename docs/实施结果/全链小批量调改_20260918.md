## 一、宿主七项缺陷逐条核实结论与修复

### 缺陷1：mine 把 train+validation 一起拟合；标签用字符串猜路径、未知回落0 —— **属实，已修复**

核实（修复前代码）：
- `src/pipeline.py` 旧 `mine()`：`records` 取 train+validation 全部，
  `feature_selector.fit(df)` 与 `rule_generator.fit_and_generate(df)` 都在
  混合集上拟合；
- 标签匹配是 `for p_name in labels: if p_name in str(_source_file)` 子串
  包含再 `labels.get(pcap_name, 0)`——子串冲突文件互相误标、未命中静默类0。

修复（`src/pipeline.py::mine` 重写）：
- **清单模式**：逐记录 `label_map[r.label(task)]` 精确标签（记录→路径→
  标签），特征行带 `_label_id/_split/_capture_id/_trial_id` 元列；
- **train-only 拟合**：`FeatureSelector.fit` 与规则生成只用
  `_split=='train'` 行；validation 只作一次性离线对照（XGBoost 对照 +
  纯规则回放 `validation_report.json`）；
- **无 validation**：`validation_report.json = {"available": false,
  "reason": "清单无 validation split；不随机按会话混拆造验证集"}`，有效性
  判别证据退回训练集并显式标注 `evidence_split`，不冒充验证证据；
- **目录模式**：basename 精确匹配；未命中文件显式 `ValueError` 列名，
  不回落类0、不子串猜测。

回归证明（`tests/regression/test_chain_audit_20260918.py`）：
- `test_manifest_labels_exact_renamed_pcaps`：文件名与标签完全无关
  （改名PCAP），标签仍按清单精确对齐（逐文件断言唯一 `_label_id`）；
- `test_validation_label_perturbation_keeps_training_artifacts`：
  验证集标签扰动（appBeta→appGamma）后 `bundle/rules.json` 逐条相同
  ——若验证数据泄入拟合则规则必变；
- `test_dir_mode_exact_basename_labels_and_no_default_zero`：
  `a.pcap`/`xa.pcap` 子串冲突正确分离；`yb.pcap` 无标签显式报错；
- `test_no_validation_split_is_explicit_not_random`：无 validation 时
  明确 `available:false`。

### 缺陷2：mine/detect 各自复制提取逻辑；mine 不过滤小会话；截断用未来包；吞异常 —— **属实，已修复（一项如实记边界）**

核实：旧 `mine()` 内联复制过滤/截断/提取且**没有** `<3包/<100B` 过滤；
`runtime.extract_feature_records` 截断只重算包/字节计数，`end_time`
仍是全会话末包（**未来包时长进特征**）；提取异常 `except: continue`
零计数。

修复（`src/features/runtime.py`）：
- 新增唯一实现 `extract_feature_records_with_stats()`（过滤+截断+提取+
  `ExtractStats` 计数），`extract_feature_records` 变薄包装；
  `mine`（清单/目录）、`pipeline.detect`、`dpi_infer.extract_features_from_pcap`
  三方全部薄包装此入口，特征逻辑全工程一份；
- `truncated_session_view()`：**浅拷贝副本**（不污染原 Session），
  `end_time/duration` 取前缀末包（不用未来包），TCP state/is_closed 按
  前缀内标志重推，TLS/QUIC 指纹天然只来自前缀内包（握手在前缀后完成
  则如实呈现"无握手"）；
- 异常计入 `stats.extract_errors`（含明细，上限20条），不再静默丢分母；
- 解析层 `PCAPReader`：`max_read_packets` **真读包上限**——PCAP 格式
  改为增量逐包读文件（读满即停，不再整文件载入）；PCAPNG 整文件读入后
  在 yield 处截断（内存整读为已知限制，如实记录）。

**如实记录的边界**：`num_retransmissions/num_out_of_order` 是 ingest 期
计数，被丢弃的重传包不在 `packets` 列表内，前缀截断后无法重构——保留
全会话计数值并在代码与本报告声明（训练/推理同规则，parity 不破；未伪造
归零）。

回归证明：
- `test_read_cap_is_real_prefix_not_postFilter`：上限读13包 ==
  物理前缀文件（逐特征相等）——"读完再截样本"与"真读上限"可区分；
- `test_truncation_prefix_no_future_duration_and_no_mutation`：
  末段+120s 未来包，截断视图 duration≈前缀末包（<10s），原会话
  end_time/packets 不变；
- `test_extract_stats_counted_not_swallowed`：会话分母守恒
  （total = 记录数 + 过滤 + 失败）。

### 缺陷5：DPI 独立性/规则语义/detect 旁路/算子粒度 —— **部分属实，已修复+一项细化**

- **`--rules` 独立**：核实 `load_rule_bundle` 不导入 xgboost/sklearn，
  `engine.load_rule_bundle` 强制 `classifier=None`——该点原实现即正确，
  本轮保持并用测试继续钉住；
- **规则条件语义**：核实 `revise-rules` 的 `LEGAL_OPS` 含
  `>=,<,!=,exists` 而 `_evaluate_rule` **不实现**（合法编辑写入引擎
  静默不匹配的条件）——已补齐四个算子 + 未知算子显式不匹配；
  bundle `label_names` 数字键加载时归一 int；
- **pipeline --mode detect 旁路**：属实——旧 detect 用 `load_rules(yaml)`
  + 自己的无过滤/无截断提取。已改为：bundle 目录优先加载
  （`rules.json` 存在即 bundle），提取走共享 runtime（过滤+截断一致），
  输出行带 `observation_id`；
- **bundle 观察参数序列化**：核实 behavior bundle 的 context 配置
  （window_sec/step_sec/segment_gap_sec/max_segments/ordering/overflow）
  序列化→加载 round-trip 与 `DEFAULT_CONTEXT_CONFIG` 完全相等（实测）；
- **算子粒度**：属实——旧 `operators.py` 只有 basic/advanced 两组且各调
  `extract_all`，称"细粒度"名不符实。已细化：advanced 内按族方法切分
  （`adv_multiscale/adv_direction/adv_distribution/adv_complexity/
  adv_cross`，特征名→族映射由"各族方法在合成会话上的实际产出"动态推导，
  防硬编码漂移；basic 产出先入表防 marker 误判）；昂贵族
  （adv_complexity：近似熵/Hurst）仅在需要时调用；保留粗组兼容层
  （旧 bundle/旧测试语义不变）。验证：族级调用计数（只需
  basic+distribution 时 complexity 计数=0）+ 全族输出与
  `basic/advanced.extract_all` 逐特征 parity（测试
  `test_operator_families_fine_grained_and_parity`）；CLI
  `--on-demand` 实测该审计 bundle 只激活
  `basic/adv_multiscale/adv_direction/adv_complexity`（跳过
  distribution/cross 两族），预测与全算一致。

### 缺陷6：行为背景窗训练被丢 → 无约束误报 —— **属实，选项化修复+合成验证**

- 评价侧（必改）：行为评价现在单列背景FPR（缺陷3修复），不再只报
  行为窗成绩；
- 训练侧：mine 新增 `--include-background`（默认关闭保留旧口径），
  背景窗作为显式类别入训练；
- **小合成实验**（fixture_m2，train g1/g2 → val g3，37 窗口）：

| 方案 | acc | macro-F1 | macro-FPR | 背景FPR | text_chat FPR |
|---|---|---|---|---|---|
| 背景窗丢弃（旧口径） | 0.865 | 0.932 | 0.119 | **1.0**（5/5全误报） | 0.238 |
| 背景显式类（--include-background） | **0.946** | **0.971** | **0.048** | **0.4** | 0.095 |

  validation 改善（acc +8.1pp、macro-FPR 减半、背景FPR 1.0→0.4）且
  无标签泄漏（背景类只用 train 窗口训练）→ **保留该选项**；默认仍关闭，
  交付口径按需开启。如实声明：背景边缘窗（与行为区间重叠≥50%边界）仍有
  2/5 误报，属 M2 已知边界，未完全解决。

### 缺陷7：固定5折CV按会话泄漏 + 小样本 —— **属实，已修复**

修复（`optimized_generator.fit_and_generate(validation=, groups=)`）：
- 有显式 validation → 验证集一次对照（不参与拟合），输出明确标注
  "离线对照，非规则DPI成绩；验证集不参与拟合"；
- 无 validation 但有采集组 → GroupKFold（同采集组不跨折，
  `min(5, 组数)` 折）+ **组-类完全重合守卫**（组=类时任何组折训练集
  单类，CV 不可拟也不可信，明确跳过——fixture_m2 即此情形）；
- 都没有 → 明确打印跳过，不按会话随机折。
- **不再把 XGBoost 成绩当规则DPI成绩**：ENS 规则在 bundle 推理路径
  一律跳过（`type=ensemble_classifier`），规则成绩只来自
  decision_tree/statistical 规则回放。

## 二、小批量前后对比（同输入/同划分/同测试集）

输入：`cstnetqq` 清单（六类网站流量，11 train_val 文件 + 6 test 文件），
